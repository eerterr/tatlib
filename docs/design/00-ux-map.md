## 2. Порядок экранов и переходы

```
Точка входа 1 «если только скачали»
  → Welcome «Рәхим итегез!»
      → ромб «Есть регистрация?»  да → Теркәлү (!)   нет → Керү (!)
      Теркәлү → Level intro → Тест узарга → Quiz 1/5 → Level result → Library
                              → Үзем күрсәтермен ──────────────────→ Level result
      Керү → ромб «Закрыто ли приложение на какой-то книге?»  да → Reader   нет → Library
Точка входа 2 «если уже скачано» → тот же ромб «Закрыто ли…»
Library → Book detail → Reader → Recap → (Укырга) Reader | Library
Нижняя навигация: Library · Scanner · Search · Profile(нет экрана)
```

(!) В Figma подписи «да/нет» на ромбе «Есть регистрация?» ведут наоборот: «да» → регистрация, «нет» → вход. Логически должно быть «да» → Керү. В макетах рисуем логичный вариант.

## 4. `critical-analysis-first`: числа и факты из базы и кода

```
NUMBERS_FROM_DATA (backend/tatar_adaptive.db, 20.09.2026):
- books: 4 строки. id 1 «Су анасы» 1908 · id 2 «Шүрәле» 1907 · id 3 «Нәҗип» year=NULL · id 4 «Алтын әтәч» 1908
- жанры: 1,2,4 = «сказка в стихах»; 3 = «рассказ». Колонки level в books НЕТ
- book_stats (word_count / unique / text_blocks): 1: 413/292/28 · 2: 929/623/4 · 3: 1560/731/32 · 4: 1500/845/29
- text_complexity.estimated_level: 1 B1 · 2 B1 · 3 B1 · 4 B2; rare_word_ratio = 0.15 у всех четырёх
- text_blocks: 93, adapted_text и russian_text заполнены у всех 93
- users: 1 строка (id 1, age 18, profile_level B1, имени нет). user_level_state: score 50, level B1, confidence 0.8
- reading_sessions 0 · user_word_events 0 · level_history 0 · adaptation_events 0
- word_events (demo_user): 4 строки — «көне», «Эссе», «көне.», «һавада», все book_id=1
- MockData.kt: 3 книги (slug-id), Нәҗип = «Повесть», 1913, B2; Шүрәле A2, progress 0.22; progressStats 184/12/68 %

MATH_CHECK:
- lexical_diversity = unique/word_count: 292/413 = 0.7070 ✓ · 623/929 = 0.6706 ✓ · 731/1560 = 0.4686 ✓ · 845/1500 = 0.5633 ✓
- /api/events/stats для demo_user: total_translations = 4; unique = COUNT(DISTINCT LOWER(word)) = 4
  («көне» и «көне.» считаются разными — точка не срезается при записи, clean_word применяется только при переводе)
- Страницы ридера = blocks.chunked(4): книга 1 → 7 стр · книга 2 → 1 стр (929 слов на одной странице!) · книга 3 → 8 · книга 4 → 8
- Уровни: API BookDto.level ← бэкенд поле level не отдаёт (в books его нет) → parseLevel(null) = B1 для всех 4 книг
```

Рассинхроны, вынесенные вперёд:

1. **Уровни книг в трёх местах разные.** База (`text_complexity`): B1 B1 B1 B2. Mock: B1 A2 B2 (три книги). API: всегда B1 (поле не отдаётся). Макеты — по `text_complexity`. Бэкенд не трогаем, вопрос владельцу: отдавать `estimated_level` в `/api/books`.
2. **`rare_word_ratio = 0.15` у всех четырёх книг** — константа, не измерение. В интерфейсе не показывать.
3. **Mock выдумал факты о «Нәҗип»**: «Повесть, 1913». В базе — «рассказ», год пуст. Фактор запрета из PROMPT § 9.
4. **Шүрәле = 1 страница** из-за `chunked(4)` при 4 блоках. Дизайн ридера обязан работать на длинной прокручиваемой странице; счётчик «1 / 1» выглядит сломанным — решение в фазе 4 (см. таблицу).
5. **Маршрут `RECAP` мёртвый**: `Routes.recap()` никто не вызывает, из ридера нет действия «завершить». В базе 0 сессий. Макет Recap — пустое состояние; переход — открытый вопрос.
6. **Статистика прогресса — `word_events`, а не `user_word_events`**: код и бэкенд считают по таблице `word_events` (demo_user, 4 события), а таблицы уровня (`user_level_state`, `level_history`) экран не читает. График по времени строить не из чего (level_history пуст).
